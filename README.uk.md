# 🏷️ Наліпки харчових продуктів для Brother QL-700

Невеликий веб-застосунок для друку харчових наліпок: відкрив сторінку з
будь-якого пристрою в мережі → вибрав продукт → вписав вагу → Brother QL-700
надрукував фінську етикетку за вимогами до харчових продуктів — склад,
алергени, харчова цінність, дати виготовлення та придатності, вага, ціна.
Дата, термін придатності й ціна рахуються автоматично. Продукти зберігаються
в одному файлі `products.json` і редагуються через вбудовану веб-адмінку.

```
[QL-700] --USB--> [Docker: цей застосунок] <--Wi-Fi--> [Планшет/ноут: браузер]
```

## Два типи наліпок

- **`frozen`** (заморозка) — повна етикетка: склад, алергени (друкуються
  жирним), інструкція приготування, умови зберігання, харчова цінність
  /100 г, дати, вага, ціна (`Hinta: 5,25 € (15 €/kg)`).
- **`deli`** (салати/делі) — коротка: склад одним абзацом, вага + ціна
  (`Paino: 500 g | Hinta: 7,50 € (15 €/kg)`).

Дати скрізь у форматі `18.07.2026`. Ціна рахується з `price_per_kg`:
`ціна = вага(кг) × ставка`, формат `x,xx €`.

На сторінці друку є **пошук** (по назві та укр. примітці) і **вкладки
категорій** (поле `category` продукту, вільний текст). Інтерфейс адаптовано
під телефон і планшет.

## Що всередині

| Файл | Призначення |
|------|-------------|
| `app.py` | рендерить етикетку (Pillow, авто-висота) і шле в принтер (`brother_ql`); також віддає сторінку друку та адмінку |
| `products.json` | каталог продуктів з усіма полями (див. нижче) |
| `Dockerfile`, `docker-compose*.yml` | збірка й запуск |

## Швидкий старт

### 🧪 Дев-режим — без принтера (mock)

Базовий `docker-compose.yml` стоїть у режимі `PRINT_MODE=mock`: замість друку
кожен «друк» зберігає наліпку як PNG у `./output/` — так на будь-якій машині
перевіряєш список, вигляд наліпок, дати й ціни (USB-принтер у Docker Desktop
під Windows/macOS однаково не прокидається).

```bash
docker compose up --build
```

Відкрий **http://localhost:5000** → тицяй продукти. Кожен «друк» кладе PNG у
`./output/`.

### 🖨️ Бойовий режим — реальний друк по USB

Той самий код, просто додаєш серверний оверлей — він вмикає реальний друк і
пробросює USB-пристрій у контейнер:

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

На хості принтер має бути видно як `/dev/usb/lp0` (модуль ядра `usblp`).
Далі з будь-якого пристрою в мережі відкриваєш `http://<сервер>:5000`.

<details>
<summary>Хост як Proxmox VM / LXC</summary>

Найнадійніший варіант — **VM з пробросом USB по ID** (переживає перетики
кабелю й перезавантаження). USB-ID QL-700: `04f9:2042`.

```bash
# на хості Proxmox, <vmid> — id твоєї VM з Linux + Docker
qm set <vmid> -usb0 host=04f9:2042
```

Усередині VM перевір, що принтер видно як символьний пристрій:

```bash
ls -l /dev/usb/lp0
```

Якщо шляху немає — переконайся, що завантажений модуль ядра `usblp`
(`modprobe usblp`).

Альтернатива — привілейований **LXC** замість VM. Тоді в
`/etc/pve/lxc/<id>.conf` додай:

```
lxc.cgroup2.devices.allow: c 180:* rwm
lxc.mount.entry: /dev/usb/lp0 dev/usb/lp0 none bind,optional,create=file
```

VM простіший і стабільніший — раджу починати з нього.

</details>

## ⚙️ Керування продуктами (адмінка)

Відкрий **http://\<сервер\>:5000/admin** (або кнопка «⚙️ Керування» на
сторінці друку):

- список усіх продуктів → **Редагувати** / **Видалити**;
- **+ Додати продукт** — форма з усіма полями, яка адаптується під тип
  (для делі поля харчової цінності приховані);
- `id` генерується автоматично зі slug назви (унікальний);
- зміни одразу пишуться у `products.json` (write-in-place, бо файл
  bind-mount).

### Редагування `products.json` вручну

Заморозка:

```json
{
  "id": "krepit-kanan", "type": "frozen",
  "name": "KREPIT KANAN KANSSA", "note_uk": "Млинці з куркою",
  "price_per_kg": 15.0, "shelf_life_days": 184,
  "frozen_mark": "pakastettu tuote",
  "ingredients": ["Taikina: ...", "Täyte: ..."],
  "allergens": "Sisältää gluteenia, munia ja maitotuotteita.",
  "instructions": "Lämmitä ...", "storage": "Säilytä -18 °C:ssa ...",
  "nutrition": {"energy_kj": 850, "energy_kcal": 205, "fat": "8 g",
                "saturated": "2 g", "carbs": "22 g", "protein": "10 g", "salt": "1 g"}
}
```

Делі:

```json
{
  "id": "olivier-makkara", "type": "deli",
  "name": "OLIVIER-SALAATTI MAKKARALLA", "note_uk": "Олів'є з ковбасою",
  "price_per_kg": 15.0, "shelf_life_days": 10,
  "ingredients_text": "keitetty peruna, porkkana, ..."
}
```

- `id` — унікальний, без пробілів. `note_uk` — внутрішня примітка, на наліпку
  **не** друкується.
- `shelf_life_days` — термін придатності; `Parasta ennen` = «сьогодні +
  днів».
- `category` (необов'язково) — вільний текст для вкладок категорій на
  сторінці друку.

## Налаштування

Через `environment` у `docker-compose.yml` / prod-оверлеї:

| Змінна | За замовч. | Опис |
|--------|-----------|------|
| `PRINT_MODE` | `real` | `real` = друк на принтер; `mock` = зберігати PNG у `OUTPUT_DIR` (базовий compose ставить `mock`) |
| `PRINTER_MODEL` | `QL-700` | модель принтера |
| `LABEL_SIZE` | `62` | тип стрічки: `62` = безперервна 62мм (DK-22205). Для висічених — свій код, напр. `29x90` |
| `PRINTER_DEVICE` | `/dev/usb/lp0` | шлях до принтера |
| `PRINTER_BACKEND` | `linux_kernel` | бекенд `brother_ql` |
| `PRODUCTS_FILE` | `products.json` | шлях до каталогу продуктів |
| `OUTPUT_DIR` | `/app/output` | куди падають PNG у mock-режимі |
| `PRINT_HQ` | `false` | `false` = швидший друк (стандартна якість), `true` = чіткіше але повільніше |
| `LABEL_SCALE` | `1.1` | масштаб шрифтів наліпки (1.0 = базовий, 1.1 = +10%) |
| `SECRET_KEY` | `dev-only-secret` | секрет Flask-сесії (потрібен лише для flash-повідомлень); у проді постав свій |

Список підтримуваних розмірів стрічки:

```bash
docker compose exec labels brother_ql info labels
```

## Якщо не друкує

- `ls -l /dev/usb/lp0` є на хості? Якщо ні — принтер не прокинувся (див.
  розділ про проброс вище).
- Права: пристрій зазвичай `root:lp 660` — контейнер працює від root, доступ
  є.
- Логи: `docker compose logs -f labels`.
- Перевір друк напряму, повз застосунок:
  `docker compose exec labels brother_ql -b linux_kernel -p /dev/usb/lp0 -m QL-700 print -l 62 <файл.png>`

## Примітка про безпеку

Застосунок — разом з адмінкою — розрахований на **довірену локальну мережу**
і **не має автентифікації**: будь-хто з доступом до порту 5000 може друкувати
наліпки й редагувати каталог продуктів. Не виставляй його в інтернет; якщо
потрібен віддалений доступ — ховай за VPN або reverse proxy з авторизацією.
